# Diverge Methods

Used in Phase 2 **only when** the idea core stays fuzzy — the user can't state it
in one sentence after two attempts, or explicitly asks for options.

Pick 3 methods. Vary the category (don't pick three generative methods). Output
each method's results visibly before converging — the user must see the material
being narrowed, not just the conclusion.

## Catalog

| Method | Category | Use when | Output |
|---|---|---|---|
| **Question Storming** | Generative | The problem itself is unclear | 10-20 questions, no answers — then cluster |
| **First Principles** | Analytical | Everything is assumed and inherited ("AI because everyone does AI") | Strip to irreducible truths, rebuild |
| **Six Thinking Hats** | Perspective | One viewpoint dominates the discussion | Findings per hat: facts / feelings / risks / benefits / creativity / process |
| **Pre-mortem** | Risk | The idea seems obviously good (suspiciously so) | "It's 2 years later and this failed — why?" |
| **Jobs-to-be-Done** | Analytical | The user describes features, not needs | What job is being hired? What's the current workaround? |
| **Analogy Transfer** | Generative | Stuck in one frame | What other domain solved this shape of problem? |
| **Constraint Removal** | Generative | Constraints are treated as laws | "If time/money/data were unlimited…" then re-add constraints one at a time |
| **Devil's Advocate** | Perspective | To pressure-test conviction before investors do | Strongest case AGAINST, stated fairly |

## Default trio

**Question Storming + First Principles + Six Thinking Hats.** Covers the three
things fuzzy ideas need: opening the space, ground truth, and multiple lenses.

*Adapted from pocketto's `brainstorming-methods.csv` pattern (diverge with a
selection rationale per method).* `[C]` `open` — method catalog is practitioner
convention (Osborn's brainstorming lineage, de Bono's Six Hats `[B]` book).

## Execution rules

1. State a one-line rationale per chosen method: "Chose [X] because [reason]."
2. Run each method **against this specific idea** — generic output is useless.
3. Diverge fully before converging at all. Do not evaluate mid-divergence.
4. Surface **2–3 directions**, not more. Each gets: name, 1-2 sentences, main
   advantage, main risk. Cite constraints for the recommendation.
5. Record what got discarded **and why** — the discarded reasoning is often what
   the user pushes back on.
