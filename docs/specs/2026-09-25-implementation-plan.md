# deckto — Implementation Plan

**Spec:** `docs/specs/2026-09-25-deckto-design.md` (approved)
**Research:** `docs/research/frameworks-methodology.md`
**Discipline:** writing-skills TDD for every skill (RED → GREEN → REFactor); `node --test` for CLI; one phase at a time, each phase verifiable before the next starts.

---

## Phase 0 — Repo scaffold + config (foundation)

**Deliverables:**
- `package.json` (name `deckto`, Node ≥18, `bin: { deckto }`), `deckto.config.json`, `.gitignore`, `LICENSE` (MIT), `CHANGELOG.md`, `.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json` (pocketto-shaped)
- `deckto.config.json` schema: `fonts.minBodyPt: 14`, `fonts.minTitlePt: 36`, `fonts.statCalloutPt: 60`, `words.maxBodyPerSlide: 25`, `visual.minElementsPerSlide: 1`, `review.maxAutoIterations: 2`
- `docs/` dirs already exist; add `skills/`, `cli/`, `test/` skeletons

**Verify:** `node -e "JSON.parse(fs.readFileSync('deckto.config.json'))"`; `npm test` runs empty suite green; manifest JSON validates.

## Phase 1 — CLI skeleton + `init` + `doctor`

**Deliverables (TDD):**
- RED: `test/cli.init.test.js` (scaffolds `deck/<slug>/` with the 5 artifact templates), `test/cli.doctor.test.js` (reports node version, soffice/pdftoppm presence, JSON envelope shape `{ ok, command, version, data, error }`)

**Verify:** `node --test` green; `npx deckto doctor --json` matches envelope contract.

## Phase 2 — CLI static QA (the enforcement core) — before skills, because tests define the contract

**Deliverables (TDD):**
- Fixtures: `test/fixtures/known-bad/` — `small-font.pptx` (10pt body), `wordy.pptx` (40-word slide), `no-insight.pptx` (notes without `INSIGHT:` line), `empty-insight.pptx` (`INSIGHT:` present, empty), `no-notes.pptx`; `test/fixtures/known-good/good.pptx`
- RED tests: each bad fixture → expected finding code (`FONTSIZE_LOW`, `WORDS_OVER_BUDGET`, `INSIGHT_MISSING`, `INSIGHT_EMPTY`, `STORYLINE_MISMATCH` when storyline provided); good → zero findings; exit code non-zero on findings
- GREEN: `cli/lib/pptx-static.js` (unzip + XML parse of `ppt/slides/*.xml`, `ppt/notesSlides/*.xml`, font sizes `sz` attrs, word counts, `INSIGHT:` first-line check), `cli/commands/qa-static.js`
- REFactor: `deckto qa report --findings` merges vision findings JSON → `qa-report.md` with scope classification + loop directive; iteration counter logic (`review.maxAutoIterations` → `REVIEW_BLOCKED`)

**Verify:** full `node --test` green; fixture decks generated by a script (`test/fixtures/make-fixtures.js`) so they're reproducible.

## Phase 3 — Support primitive: vendored `pptx` + `humanizer` (modified)

**Deliverables:**
- `skills/pptx/` — vendored from local `~/.agents/skills/pptx`, trimmed to deckto's needs (pptxgenjs guide, thumbnail/render scripts, QA prompt), plus a deckto note: INSIGHT line frozen during any humanizer pass
- `skills/humanizer/` — vendored, short-text profile, pitch-cliché watchlist added (revolutionary/seamless/game-changing/disrupt), `INSIGHT:` line exemption rule added

## Phase 4 — Flagship #1: `pitchdeck-pitch-me` (TDD)

**Deliverables:**
- RED: 3 baseline scenarios WITHOUT the skill (application: vague idea; edge-case: user who answers "idk"; missing-info: no data/assets known) → record actual agent failures verbatim in `test/skill-baselines/pitch-me-baseline.md`
- GREEN: `skills/pitchdeck-pitch-me/SKILL.md` — phases 0–4 per spec: Preflight → framework questioning A–F (one per message, `unknown` recording) → diverge (3 methods) → converge + SCQA frame → write `pitch.md` + 3-option handoff. Hard Gates: GATE A (no artifact work before A–F), GATE B (user confirmation ≠ silence). `references/question-framework.md` (per-question rationale + tiered sources), `references/diverge-methods.md`
- REFactor: pressure scenarios (user pushes to skip questions; time-crunch "just make it") → add explicit counters
- GREEN verification: re-run the 3 baselines WITH skill → must comply (A–F filled or `unknown`, one question per message, handoff gate shown)

**Verify:** `pitch.md` template output complete; skill frontmatter ≤1024 chars; description = triggers only (CSO rule).

## Phase 5 — Flagship #2: `pitchdeck-grinding` (TDD)

**Deliverables:**
- RED: 3 baselines (application: full `pitch.md` → storyline; edge-case: SCQA complication missing; missing-info: phase-D data `unknown`)
- GREEN: `skills/pitchdeck-grinding/SKILL.md` — phases 0–5: read `pitch.md` (block on unexplained gaps) → master title (Minto) → arc annotation (Duarte tags) → full-detail slides (assertion title, insight, body ≤budget, visual, visual_source, evidence, notes_draft) → `design-spec.md` (section-typed patterns per Cabezas, palette dominance, motif, font floors) + `usecase-flow.md` → gates (master-title traceability, non-empty insight, word budget) → handoff
- Hard Gates: GATE — no handoff with empty insight / over-budget slide / untraceable slide; word-budget check against `deckto.config.json`
- `references/arc-tags.md`, `references/slide-anatomy.md` (assertion-evidence + SUCCESs insight test), `references/design-spec-template.md`
- REFactor + GREEN verification as Phase 4

**Verify:** given the Phase-4 `pitch.md`, skill produces `storyline.md` where every slide satisfies the YAML schema (add `test/schema/storyline.schema.json` + validator used by both skill gate and future CLI).

**Deliverables:**

## Cross-phase rules

1. **No skill without failing test first** (writing-skills Iron Law) — baselines committed before SKILL.md.
2. **Every QA threshold read from `deckto.config.json`** — never hardcode in skill prose or CLI.
3. **Every research claim tagged** `[EMPIRICAL]`/`[BOOK/STANDARD]`/`[CONVENTION]` with tier+access in `references/`.
4. Phase gate: previous phase's tests green before next phase starts.
5. Humanizer rule everywhere: `INSIGHT:` line 1 is frozen.
